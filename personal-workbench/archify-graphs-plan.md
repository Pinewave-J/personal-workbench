## 0. 为什么是这 6 张（能力边界回顾）

archify-dsh 是**图谱生成器**（节点/边/泳道/边界 + 独立 viewer），不是样式库、也不是数据图表库。
所以这 6 张全部选"逻辑契约与数据流"，不做装饰；数据图表（环形图/条形图）继续由工作台自己手写 SVG 承担。

工具事实（已核）：
- 已安装 `@tt-a1i/archify-dsh@0.1.0`，**skill-only 包**（不注册原生工具），只能 `node <skill>\bin\archify.mjs …`
- 可用类型：`architecture` / `workflow` / `sequence` / `dataflow` / `lifecycle`（+ common schema）
- 本机 Chrome 已装；但**本会话沙箱拒绝启动 chrome.exe**（上轮实测），visual-check 预计跑不了

## 3. 「系统图谱」页（把「知识库」占位页改造）

- **后端**：新增 `app.use("/api/v1/graphs", express.static(<workspace>/graphs))`；路径用 `fileURLToPath` 解析（`backend/src` → `../../graphs`），不硬编码。只读、无鉴权，与现有接口一致。**需要重启后端才生效。**
- **前端**：`viewKb()` → 图谱页；导航项 `{ id:"kb", ico:"book", label:"系统图谱" }` —— **id 保持 `kb` 不变**，避免深链 `#/kb` 失效。
- **页面结构**：左侧清单（标题 + 一句话说明 + 类型标签 + 节点数）；右侧 iframe **只加载当前选中那张**（省体积）；顶部「在新窗口打开 ↗」「重新加载」；底部说明"图谱是独立文档，自带主题与缩放/导出"。
- 图谱 viewer 自带深浅主题，与工作台主题开关 **不联动**（iframe 内独立）。若你要联动，需要 archify viewer 接受主题参数——我没验证过它是否支持，默认不做。

## 4. 执行顺序与授权（把弹窗压到最少）

1. 读 1 个 schema + 1 个同类型 example，写 6 个规格 JSON（工作区内写入，**零授权**）
2. **一条组合命令**批量 `deliver` 6 张（逐张汇报结果，单张失败不中断其它）→ **只 1 次授权弹窗**
   - 本机 `workspace-write` 下 `node <脚本>` 会被拒；按既有协议：同一命令重试一次即完成授权
3. 后端静态路由 + 前端图谱页 + `index.json` 清单
4. 验证（§5）

## 6. 风险与取舍

- **1 次授权不可避免**（skill-only 包）。批量做只花 1 次。
- **体积**：每张 HTML ≈ 612KB（模板自带 viewer），6 张约 3.7MB，均在工作区内；iframe 按需加载。
- **字体走 Google Fonts CDN** → 离线时降级为系统字体，功能不受影响、观感略变。
- **图谱是静态文档**：后端逻辑改了要重新生成。对策：`graphs/README.md` 写清"依据 + 一条命令重生成"。
- **workflow 渲染器几何硬约束**：标签不得换行，宽度按"中文=2 字符宽 ×6.8px"算，所以**中文标签必须短**（约 8~12 字以内），长句要下沉到卡片；泳道内节点列位也有互斥规则。我会按已核对过的常量写规格，避免反复试错。
- **不做**：数据驱动实时渲染（archify 是作者化规格，不是图表库）。
