# 首页日历模块 · 设计文档

> 目标：在首页新增「日历」区块，一屏看清**每天要办的事**；点某天看明细，点条目直接处理。
> 状态：**已实现并验收**（2026-09-11，P1–P5 全部完成）
> 编写：2026-09-11

---

## 1. 目标与范围

**做**：月视图日历，聚合四类"有日期的事"，每天显示条目、当天可点开处理、可快捷新增。
**不做**（除非另行要求）：拖拽改期、周/日视图、农历与节假日、重复事件、导出 .ics、多人共享。

---

## 2. 显示什么：四类数据与归日规则

"每天要办的事"实际有 4 个来源，语义必须先定义清楚，否则日历会出现重复或漏项。

| # | 来源 | 日期字段 | 归入哪一天 | 显示规则 |
|---|---|---|---|---|
| 1 | 任务 / 待办 | `personal_task.due_date` | `due_date` | 未完成（待办/进行中）→ 按四象限配色的条目；已完成/已取消 → 灰显删除线 |
| 2 | 投标截止 / 开标 | `bid_project.deadline`（注意：`open_time` 由后端恒等于 `deadline`） | `deadline` | **两者相同则合并为一条「投标截止 / 开标」，绝不出两条**；若将来两者不同，则各自显示在对应日期 |
| 3 | 日程提醒 | `schedule_reminder.remind_at` | `remind_at` | 显示提醒类型（报名截止 / 购标截止 / 投标截止 / 开标 / 其他）；`待提醒` 才显示 |
| 4 | 客户跟进 | `customer.next_follow_date` | `next_follow_date` | 显示客户名；客户状态为 `流失` 时跳过 |

### 2.1 补充规则（容易踩坑的地方，逐条锁定）

1. **逾期未完成的任务**：仍显示在**原定日期**格内并标红（不搬到今天——搬走会让历史失真）；同时在「今天」格顶部额外放一条汇总入口「逾期 N 条待办」。
2. **无 `due_date` 的未完成任务**：集中收在日历卡片右上角「待安排（N）」入口里，不硬塞进某一天（当前库里为 0 条，将来会出现）。
3. **投标终态**（中标 / 未中标 / 流标）：默认不显示其截止日，避免历史噪声；由「含已结束」开关控制。
4. **日期比较一律用纯日期字符串**（`YYYY-MM-DD`）做本地比较，**禁止** `new Date("YYYY-MM-DD")`（这个项目已经踩过 UTC 偏移导致差一天的坑）。
5. **颜色语义**沿用现有来源：任务用四象限色、投标用状态色（与首页环形图一致），不新造一套。

## 3. 数据来源：双通道（避免"要等后端重启"）

### 通道 A（首选）：新增 `GET /api/v1/calendar?month=YYYY-MM`

一次性按**日期区间**聚合四类数据，返回按日期分桶的结果：

```jsonc
{
  "month": "2026-09",
  "days": { "2026-09-11": [ {type,id,title,meta,color,status,...} ], ... },
  "overdue": [ ... ],        // 未完成且 due_date < 今天
  "undated": [ ... ],        // 未完成且无 due_date
  "counts": { "tasks": 14, "bids": 3, "schedules": 1, "customers": 2 }
}
```

**为什么必须专门开接口**：现有 `/tasks?month=` 的过滤是
`(t.month_tag = ? OR t.due_date LIKE ?)`（`tasks.js:164`）——它按"归属月"和"截止月"取并集，
会把"归属月是 9 月但截止日在 10 月"的周期任务混进 9 月日历。日历必须严格按**截止日**分桶。

### 通道 B（回退）：前端用 4 个现有 GET 自行拼装

接口不存在时（后端未升级）自动降级，**不阻塞功能**：

| 请求 | 用途 | 必要的后处理 |
|---|---|---|
| `/tasks?scope=all&month=YYYY-MM&pageSize=500` | 任务 | 再按 `dueDate` 前缀过滤，修正上面的语义偏差 |
| `/projects?startDate=YYYY-MM-01&endDate=YYYY-MM-末&pageSize=200` | 投标截止 | 直接用（已按 deadline 区间过滤） |
| `/schedules` | 日程提醒 | 按 `remindAt` 前缀过滤（接口 LIMIT 200） |
| `/customers?pageSize=500` | 客户跟进 | 按 `nextFollowDate` 前缀过滤 |

> 这套双通道与 `byIndustry` 的处理一致：**不重启后端也能用，重启后自动切到更准的单请求通道**。

## 4. 放在首页哪里 & 长什么样

**位置**：磁贴（8 个入口）下方、两个环形图上方，**整宽卡片**——首页第一眼的"今天要干什么"。
备选位置（按你的选择调整）：与「今日提醒」同一排 / 页面最底部。

```
┌─ 日历 ──────────────────────────────────────────────── 待安排(2) ─┐
│ ‹  2026年9月  ›   [今天]    类型：☑任务 ☑投标 ☑日程 ☑客户  只看未完成 │
├──────────────────────────────────────────────────────────────────┤
│ 周一   周二   周三   周四   周五   周六   周日                    │
│  31    1     2      3      4      5      6                       │
│ ┌────┐ … 每格：日期数字 + 最多 3 条彩色条 + 超出显示「+N」          │
│ │ 11 │ ● 某化工项目面试准备                                        │
│ │ ●●●│ ● 跟进：某某港务…（客户）                                     │
│ └────┘ ● 某某项目投标截止/开标                        ← 逾期格左上角红点 │
├──────────────────────────────────────────────────────────────────┤
│ 9月11日（今天）· 3 件事                                           │
│  [任务] 某化工项目面试准备        重要紧急 · 待办      [完成] [打开]  │
│  [客户] 跟进：某某港务…  电话 · 待办          [完成] [打开] │
│  [投标] 某某项目…委托监理服务        投标截止/开标 09-20  [打开]       │
└──────────────────────────────────────────────────────────────────┘
```

**交互**：

- 网格：**周一为第一列**（中文习惯，`offset = (getDay()+6)%7`）；今天高亮描边；非本月日期淡化；行数按需 5 或 6 行，网格设固定 `min-height` 避免切换月份时跳动。
- 点某天 → 卡片内**展开当天明细**（默认选中今天），再点一次收起；明细里每条都有对应的「打开」（任务→任务弹窗、投标→项目弹窗、日程→日程弹窗、客户→客户详情）。
- 任务条目支持**快捷完成**（复用 `POST /tasks/:id/complete`，客户任务会照旧弹出"下次跟进日期"询问）。
- 选中某天时点「+ 新增待办」→ 任务弹窗的截止日**预填该天**。
- 类型筛选与「只看未完成」是纯前端过滤，不重新请求；选择记在 localStorage。

## 5. 窄窗口与响应式

| 宽度 | 布局 |
|---|---|
| ≥1100px | 7 列网格 + 右侧明细区（两栏） |
| 760~1100px | 7 列网格保留，格子变窄：条目只显示圆点 + 计数；明细区移到网格下方 |
| <760px | **切换为「按日期分组的清单」**（本月待办列表，日期作分组标题）——比横向滚动的日历可用 |

必须遵守既有布局约束：容器 `min-width: 0`、文本单行截断、**不产生整页横向滚动**（这是刚修过的回归点，会写进防回归测试）。

## 6. 性能与实现要点

- 数据量很小（当前：21 任务 / 7 项目 / 1 日程 / 2 客户），单月 1~4 个请求；**按月份缓存**，只有切月才重新取。
- 渲染是纯字符串拼装，**零新依赖**，与现有 `renderMain` + `bindViewEvents` 模式一致。
- 复用现有工具：`todayStr` / `daysLeft` / `fmtYMD` / `esc` / `statusBadge` / `quadrantColor` / `bidDistColor` / `svgIcon` / `Store` / 令牌配色。
- 新增代码规模预估：前端日历逻辑 200~250 行、CSS 80~120 行、可选后端接口 ~60 行；**不新增数据库表**（日历是纯读视图）。
- 日历卡片提供**折叠**按钮（状态存 localStorage），避免首页过长。

## 8. 验收与测试（我会逐项跑）

1. **分桶单元测试**（node，无需浏览器）：月首/月末、跨月、闰年 2 月（2028-02）、周一起始偏移、5 行 vs 6 行月份 —— 逐个断言。
2. **语义断言**：`deadline == open_time` 时**不出两条**；逾期任务留在原日期且被标记；已完成任务默认灰显；无日期任务进「待安排」；终态项目默认不出现。
3. **后端接口交叉核对**（副本库 + 8790，跑真实数据）：`/calendar` 每日条目数与 `/tasks`、`/projects`、`/schedules`、`/customers` 的结果逐日比对一致。
4. **回退通道一致性**：对着**未升级的 8787** 跑一遍前端拼装逻辑，确认与通道 A 结果一致。
5. **布局防回归**：不产生整页横向滚动；`min-width: 0` 守卫仍在；窄窗清单模式的规则存在。
6. **主题审计**：日历新增颜色全部走令牌，浅色主题有对应覆盖；WCAG 对比度达标。
7. **需要你的眼睛**：日历的实际观感、格子密度是否合适 —— 我没有浏览器截图能力，这一点一直如实说明。

## 9. 风险与取舍

| 风险 | 对策 |
|---|---|
| 首页变长 | 卡片可折叠 + 每天最多 3 条（超出显示 +N），状态记 localStorage |
| 首页请求数增加 | 按月缓存，切换月份才请求；通道 A 只 1 个请求 |
| 回退通道语义偏差 | 前端补 `dueDate` 前缀过滤（已识别，写进实现） |
| 后端重启依赖 | 双通道消除：不重启可用，重启后更准 |
| 日期时区坑 | 全链路纯日期字符串比较，禁用 `new Date("YYYY-MM-DD")` |
| 拖拽改期等期待外溢 | 明确列入"不做"，需要再单开阶段 |
